## 1. 建设背景与目标

目标是建设一套行业标准的汽车 DMS：既支持授权经销商网络管理，也支持厂家直营门店；维修业务从预约到交车闭环；备件库存参考富勒 WMS / SAP EWM 的库位、批次、预留与 FIFO 消耗模型；满意度与投诉形成闭环；发票可对接税控平台。技术栈按要求采用 Java 8 + Vue。

## 4. 核心业务流程

### 4.1 维修工单状态机

```
预约(可选) → RECEIVED 接车 → DIAGNOSED 诊断 → QUOTED 报价 → CONFIRMED 客户确认 → DISPATCHED 派工(FIFO 预留备件)
→ REPAIRING 维修 → QC_PENDING 待质检 → QC_PASSED 质检合格(消耗备件) / 质检不合格返工(不重复扣库)
→ SETTLED 结算(自动开票申请、保修金额>0 自动生成索赔草稿) → DELIVERED 交车(更新里程/保养、自动创建调研)
任意未结算节点可 CANCELLED 取消并释放预留
```

### 4.2 整车销售

```
NEW → ALLOCATED(分配整车库存) → 金融申请/审批 · 保险登记 · 收款流水 → INVOICED(真实发票草稿)
→ DELIVERED(校验 PDI 通过、贷款已批、尾款结清) → 自动创建销售满意度调研；取消订单释放整车库存
```

### 4.3 保修索赔（PR #30）

```
DRAFT → SUBMITTED → APPROVED(核价，可勾选需回收配件行 → PARTS_RETURNING → PARTS_SHIPPED → APPROVED)
                  ↳ RETURNED(退回补充后可重提)  ↳ REJECTED
APPROVED → 结算批次 SETTLED → 付款 PAID；OEM 审核/签收/结算，经销商提交/发货，财务只读
```

### 4.4 发票与税控

```
DRAFT → ISSUING(平台受理 pending) → ISSUED；ISSUED → RED_FLUSHING → RED_FLUSHED(红票开具后)
HTTP 网关：POST {endpoint}/issue|query|red-flush，X-App-Id / X-Timestamp / X-Nonce / X-Sign(HMAC-SHA256)，
超时可配，非 2xx 转失败；回调 /api/invoice/callback 带 token 校验
```

## 5. 安全与权限

| 角色 | 数据范围 | 可写范围 |
|---|---|---|
| ADMIN | 全网 | 全部，含用户管理 |
| OEM | 全网 | 网络 / 指导库 / 车型 / 备件主数据 / 调研模板 / 索赔审核与结算 |
| DEALER_MANAGER | 本店 | 店内全部；不可写经销商主数据、目标、考核、指导库、调研模板、用户、索赔审核 |
| ADVISOR 服务顾问 | 本店 | 工单全流程、客户车辆、调研答卷 / 投诉、备件预留释放 / 入库、补货、销售订单、索赔提交 / 发货 |
| TECHNICIAN 技师 | 本店 | 仅工单开工 / 完工 / 质检 |
| FINANCE 财务 | 本店 | 发票全流程、工单结算、销售开票 / 交车 / 收款 / 金融审批 |

- JWT（HS256）鉴权，生产强制 `DMS_JWT_SECRET` ≥ 32 字节；`DataScope` 对非全网角色按 `dealer_code` 隔离，跨店访问拒绝。

- 登录锁定（5 次 / 15 分钟）、按 IP 固定窗口限流（429）、自适应图形验证码（OFF / ADAPTIVE / ALWAYS）、代理 IP 可信配置。

- prod profile 不装载演示账号与演示数据，首启自动引导 admin（密码来自环境变量或一次性 WARN 日志），关闭 H2 控制台。

- 开放接口 `/api/open/ir/**` 使用 `X-Api-Key`；无效 Key 返回 401，非法请求体返回 400，幂等键防重放。
