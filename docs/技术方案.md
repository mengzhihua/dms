# DMS 技术方案

DMS 面向经销商网络：整车销售、维修工单、备件库存和向 OMS 的补货。IR 观察缺货和补货单，并触发按缺货生成、按下发。

## 1. 运行位置

| 场景 | 后端 |
| --- | --- |
| 单机 | `8080` |
| 与控制塔同机 | `8092` |

Open IR 请求头 `X-Api-Key`，种子键 `dms-open-key`。没有 Key 时，控制塔用登录口。

## 2. 主链路

```text
经销商缺货 → 生成补货单 → 下发 OMS
维修工单仍在本系统内走派工、质检、结算，不经过控制塔
```

## 3. 控制塔读

`GET /api/open/ir/snapshots`：

| dataType | 业务键 | 内容 |
| --- | --- | --- |
| `SHORTAGE` | 经销商与零件 | 缺货 |
| `REPLENISH` | 补货单号 | 状态、数量 |

## 4. 控制塔写

| 指令 | 专用口 | 作用 |
| --- | --- | --- |
| `DMS_REPLENISH_SHORTAGE` | `POST /api/open/ir/replenish-shortage` | 按 `dealerCode` 从缺货生成补货单。没有缺货则拒绝 |
| `DMS_PUSH_REPLENISH` | `/push-replenish` | 按补货单号下发 |

统一口是 `POST /api/open/ir/actions`。`targetKey` 可以是 `经销商/零件`，经销商取斜线前一段。

没有 API Key 时，控制塔登录后：

- 按缺货生成：`POST /api/oms/replenish/from-shortage?dealerCode=`
- 下发：按补货单号分页查出 id，再 `POST /api/oms/replenish/{id}/push`。纯数字目标直接当作 id

非空幂等键按 `type|业务键|key` 缓存。

## 5. 边界

控制塔不改维修工单和整车订单。补货下发的权威单据在 OMS。本系统记录的是经销商侧的补货申请和缺货。
